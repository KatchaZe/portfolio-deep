## A1 · row schema เขียนซ้ำสองรอบ 🔴 ทำก่อน

**ข้อเท็จจริง:** `refresh.analyze_row()` (watchlist) กับ `refresh.portfolio_view()` (holdings)
สร้าง dict ที่มี **key ซ้ำกัน 55 ตัวจาก 55 ตัว** — คือ schema เดียวกันทั้งอัน เขียนคนละที่ ห่างกัน 300 บรรทัด

```
analyze_row       55 keys
portfolio_view    71 keys   (55 ซ้ำ + 16 ตัวที่เป็นเรื่อง holding: shares/avg_cost/pl/…)
```

**ทำไมอันตราย:** เพิ่ม field ใหม่หนึ่งตัวต้องแก้สองที่ ลืมที่ไหนที่หนึ่ง = แท็บหนึ่งมีข้อมูล อีกแท็บไม่มี
โดยไม่มี error ให้เห็น — และ git log บอกว่า**เคยเกิดมาแล้วจริง**:
`2df2ce2 "watchlist parity (My-Portfolio fields)"`

**เสนอ:** แยก `pipeline/row.py` ที่มีฟังก์ชันเดียว

```python
def build_row(ticker, ff, val, mom, *, rev_surprises=None, fmp_on=None) -> dict
```

แล้วให้ทั้งสองที่เรียกมัน `portfolio_view` ค่อย `{**base, **holding_fields}` ต่อ

**ความเสี่ยง: ต่ำ** — เป็น extract ล้วน ๆ ไม่มี logic เปลี่ยน
**วิธีพิสูจน์:** dump row ของทั้ง 21 ชื่อทั้งสองเส้นทาง ก่อน/หลัง แล้ว diff ต้องได้ 0 ไบต์
**ได้อะไร:** −~90 บรรทัด และ bug class นี้หายไปถาวร

## A2 · `DeepV82Engine.evaluate()` ยาว 442 บรรทัด / 163 branch 🟠

ฟังก์ชันเดียวที่ยาวที่สุดและแตกแขนงมากที่สุดในระบบ ตัวถัดไปยาวไม่ถึงครึ่ง

**ข้อสังเกตสำคัญ: มันไม่ได้เขียนแย่** — มันเป็นลำดับขั้นตอนตรง ๆ ที่มีคอมเมนต์กำกับทุกบรรทัด
ปัญหาอยู่ที่ตัวแปรกลาง ~40 ตัวมีชีวิตอยู่พร้อมกันในขอบเขตเดียว จึงไม่มีอะไรกันไม่ให้
ขั้นตอนที่ 9 ไปหยิบตัวแปรของขั้นตอนที่ 3 ที่ยังคำนวณไม่เสร็จ — **ซึ่งคือกลไกของ P3-1 พอดี**
(`f.revenue` กับ `rev_1y` อยู่ในขอบเขตเดียวกัน หยิบมาหารกันได้เลย)

**เสนอ: แบ่งเป็น 5 ขั้นที่ส่งของกันเป็น dict อ่านอย่างเดียว** ตามที่โค้ดแบ่งด้วยคอมเมนต์อยู่แล้ว

| ขั้น | ฟังก์ชัน | รับ | คืน |
|---|---|---|---|
| 1 | `_capital_costs(f, rf)` | facts | wacc, ke, kd, beta_t, w_term, ke_st |
| 2 | `_returns(f, tax, w)` | facts, tax, wacc | roic, roic_used, ic, spread, roic_term, lease |
| 3 | `_growth(f, roic_used, roic_term)` | | growth, g_cap, g_stable, **rev_growth_yoy** |
| 4 | `_fair_values(f, ctx)` | ผลขั้น 1–3 | fv_peg, fv_fvp, rdcf, ydcf, anchor |
| 5 | `_score(f, ctx)` | ผลขั้น 1–4 | D, E_exec, E_econ, P, composite, reco |

**ประโยชน์จริง:** ขั้น 3 คืน `rev_growth_yoy` เป็นค่าเดียวที่ทุกคนต้องใช้ — โครงสร้างจะ **กัน P3-1
ไม่ให้เกิดซ้ำ** ตั้งแต่ต้น ไม่ใช่แค่ทำให้อ่านง่ายขึ้น

**ความเสี่ยง: กลาง** — 163 branch ต้องยกมาให้ครบ
**ทำแบบไหน:** ทีละขั้น ขั้นละคอมมิต รัน replay 21 ชื่อ diff ต้อง 0 ทุกครั้ง **ห้ามยกทีเดียว**
**คำแนะนำ:** ทำ A1 ให้จบและมั่นใจก่อน ค่อยเริ่มอันนี้

## A4 · `sec_edgar.extract()` 219 บรรทัด + `_accessors()` 111 บรรทัด 🟠

เป็นที่ที่ **ความหมายของ TTM กับ annual แยกกำเนิด** (`ttm()` vs `annual_series()`) —
