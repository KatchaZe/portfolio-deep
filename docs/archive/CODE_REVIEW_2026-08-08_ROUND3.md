## P3-1 · "1-year growth" ที่กินเวลา ~21 เดือน 🔴

### เจออะไร

`FinancialFacts.revenue` คือ **TTM** (sec_edgar รวมรายไตรมาส) แต่ `revenue_annuals[k]` คือ **ปีงบ** เรียงใหม่→เก่า
สี่จุดในเครื่องยนต์เอาสองอย่างนี้มาหารกันโดยตรง — ได้ **TTM ÷ ปีงบก่อนหน้าอีกหนึ่งปี** แล้วเรียกว่า "growth 1 ปี"

```
MSFT   TTM 318.3B ÷ FY2024 245.1B = +29.8%     ← ที่การ์ดโชว์
       FY2025 281.7B ÷ FY2024 245.1B = +14.9%  ← ที่ Microsoft ประกาศ (+15%)
```

หลักฐานจากงบที่เก็บไว้เอง — คอลัมน์ `gap%` คือระยะที่ TTM วิ่งนำปีงบล่าสุดไปแล้ว:

| ticker | TTM | ปีงบล่าสุด | gap | ที่การ์ดโชว์ | **ที่ประกาศจริง** |
|---|---|---|---|---|---|
| MSFT | 318.3B | 281.7B | +13.0% | +29.8% | **+14.9%** |
| AVGO | 75.5B | 63.9B | +18.1% | +46.3% | **+23.9%** |
| NVDA | 253.5B | 215.9B | +17.4% | +94.3% | **+65.5%** |
| CELH | 2.97B | 2.52B | +18.0% | +119.0% | **+85.5%** |
| ORCL / TSM / NVO / ASML | — | — | 0.0% | ตรง | ตรง |

**ทิศทางเดียวเสมอ** — TTM ≥ ปีงบล่าสุด ดังนั้น "actual" สูงเกินตลอด ไม่เคยต่ำเกิน

### ทำไมถึงสำคัญกว่าที่เห็น

ตัวเลขนี้ไม่ใช่แค่ตัวโชว์ — มันเป็น **ตัวหาร** ของ acceleration ที่ตัดสิน verdict:

```
accel = implied_CAGR / actual_1y
  <1.5 Plausible │ <3 Ambitious │ <5 Aggressive │ else Exceptional
```

actual สูงเกิน → accel ต่ำเกิน → **verdict ใจดีเกินอย่างเป็นระบบ** และการ์ดยังเขียนกำกับว่า
"ตลาดคิดต่ำกว่าที่ทำได้" ทั้งที่ความจริงตรงข้าม

ยังลามไปอีกสองที่ที่ใช้สูตรเดียวกัน:
* **flag billings** — MSFT ขึ้นว่า `deferred rev −1% vs rev +30%`
* **AR vs revenue (channel stuffing)** — เงื่อนไขคือ `ar_g > rev_g + 0.15` การทำให้ `rev_g` สูงเกิน
  **ทำให้ flag ยากขึ้น** คือกดสัญญาณให้เงียบ พอดีกับตอนที่ควรดัง

> คอมเมนต์ใน `index.html` บรรทัด 2045 เขียนไว้ว่า *"ตรวจที่มาแล้ว (2026-08-04): actual มาจาก
> SEC revenue_annuals ตรง ๆ ไม่มีสมมติฐาน"* — **ไม่จริง** ตัวตั้งเป็น TTM มาตลอด
> (แก้คอมเมนต์แล้วเช่นกัน)

### แก้ยังไง

เครื่องยนต์คำนวณตัวที่ถูกอยู่แล้ว — `rev_growth_yoy = revenue_annuals[0]/revenue_annuals[1] − 1`
ซึ่งเป็นตัวที่ **Demand pillar ใช้ให้คะแนนอยู่แล้ว** จึง **ส่งต่อ** แทนที่จะคำนวณใหม่จากนาฬิกาคนละเรือน

```python
rdcf = reverse_dcf(..., actual_growth=rev_growth_yoy)      # P3-1
eq   = earnings_quality(..., revenue_growth=rev_growth_yoy)
rev_g = rev_growth_yoy                                      # billings flag
```

สูตรเก่าเหลือไว้เป็น fallback ให้ caller ที่ไม่ส่งค่ามา (skill-parity tests) → พฤติกรรมเดิมไม่กระทบ

**ที่สำคัญที่สุด:** เดิม *การ์ดใบเดียว* โชว์ "actual revenue growth" **สองตัวที่ไม่ตรงกัน** —
ตัวที่ Demand ใช้ กับตัวที่ RevDCF โชว์ ตอนนี้เป็นตัวเดียวกันแล้ว

## P3-2 · วัดไม่ได้ ได้คะแนนดีกว่าวัดแล้วแย่ 🔴

`composite()` เฉลี่ยถ่วงน้ำหนัก **เฉพาะ pillar ที่มีค่า** แล้วหารด้วยน้ำหนักที่เหลือ


บริษัทเดียวกัน ข้อมูลชุดเดียวกัน ต่างกันแค่ **เราวัดไม่ได้** — แล้ว "วัดไม่ได้" มีค่า **+0.90 และอัพเรตติ้ง**

`REV-8` เคยปิดรูนี้ไปแล้วฝั่ง **Price** (`cap_reco_without_price`) แต่ทิ้งรูเดียวกันไว้ฝั่ง
**Economics ซึ่งน้ำหนักเท่ากันคือ 30%** และเป็น pillar ที่ Damodaran ถือว่าสำคัญที่สุด —
growth สร้างมูลค่าก็ต่อเมื่อ ROIC > cost of capital ถ้าไม่ได้วัด spread เลย
แปลว่า**ข้อสอบข้อที่ตัดสินว่า growth มีค่าไหม ไม่ได้ถูกทำ** จะออกมาเป็นคะแนนเต็มไม่ได้

ROIC หายด้วยเหตุผลธรรมดามาก ไม่ใช่เคสหายาก:

* **invested capital ≤ 0** เพราะเงินสดมากกว่าหนี้+ทุน — เรื่องปกติของ software/biotech ที่เงินสดหนา

**แก้:** เพิ่ม `cap_reco_without_quality()` คู่กับตัวเดิม + ขึ้น flag บอกเหตุผลบนการ์ด

### D5 ⛔ — ทำแล้ว วัดแล้ว **ย้อนกลับ** เพราะของเดิมถูก

ผมเขียนตามที่เสนอไว้จริง (เปลี่ยนไปใช้ NOPAT growth) แล้ววัดผล — **มันแย่ลงชัดเจน**:

```
HIMS  implied CAGR 16.7% → 36.2%
ELV · RKLB · AXON  →  หลุดกรอบ ("ไม่มี growth rate ไหนอธิบายราคานี้ได้")
```

พอไล่สมการก็เจอว่าของเดิมไม่ใช่การประมาณ **แต่ถูกเป๊ะ**:

```
reinvestment = ΔCapital / NOPAT
ภายใต้ sales-to-capital คงที่ (สมมติฐานของ Damodaran เอง และเป็นตัวที่ young_dcf ใช้):
    Capital  = Revenue / (S/C)        ΔCapital = Capital × x        ROIC = NOPAT / Capital
    ⇒ reinvestment = Capital·x / (ROIC·Capital) = x / ROIC          ← x คือ REVENUE growth
```

ตัวอย่างที่ชี้ขาด: revenue +20% พร้อม margin 10%→25% ⇒ NOPAT โต **200%**
แต่ทุนที่ต้องใส่เพิ่มยังเท่าเดิมคือ ΔRevenue/(S/C) — **การขยาย margin ไม่กินทุน**
คิด `g_NOPAT/ROIC` จึงเท่ากับเก็บเงินค่าขยายที่บริษัทไม่ได้จ่าย

โค้ดกลับไปเหมือนเดิมทุกบรรทัด เหลือไว้แต่คอมเมนต์ที่เขียนที่มาไว้ + test ตรึง
เพื่อไม่ให้ "ปรับปรุง" ข้อนี้ถูกทำซ้ำอีก

### D5 · reinvestment ใน reverse DCF ใช้ **revenue** CAGR หารด้วย ROIC

`reinvest = x / roic_t` โดย `x` เป็น **revenue** growth แต่สูตร reinvestment rate ของ Damodaran คือ

เป็นการประมาณที่ยอมรับได้ แต่ยังไม่มีที่ไหนเขียนกำกับไว้

## 8. T5 · แถบเทรนด์ 5 ปี บนการ์ด (feature ใหม่ 2026-08-09)

### 🔴 silent fault ที่เจอระหว่างทาง — ลำดับใน list ไม่ตรงกันระหว่าง source

`earnings_surprises` ถูกอ่านด้วย `[-1]` ทุกที่ โดยเชื่อว่า list เรียง old→new
แต่ **Yahoo parser ส่งกลับ new→old** ส่วน source อื่นส่ง old→new · บนพอร์ตจริง:

```
TSLA  [2026-03-31, 2025-12-31, 2025-09-30, 2025-06-30]   <- new→old (yahoo)
      [-1] = 2025-06-30  ←  เก่ากว่าของจริง 9 เดือน
REGN  เหมือนกัน (yahoo+finnhub)
```

กระทบ 3 ที่พร้อมกัน: **PEAD drift signal** · **การเทียบ source ว่า beat/miss ตรงกันไหม** · **วงกลม Earnings บนการ์ด**

**แก้ที่ราก** — เลิกเชื่อลำดับ ใช้ `quarter` ที่ติดมากับข้อมูล (`pead.chronological()` / `pead.latest()`)
บทเรียนเดียวกับ P3-1 เป๊ะ ๆ: **ข้อมูลที่มีวันที่ ให้ join ด้วยวันที่ อย่าใช้ตำแหน่ง**
